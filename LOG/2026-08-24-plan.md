# 4f5c86b — Bot scoped onto Cloudflare Workers with private per-person sign addresses; queue split into a build plus two user steps, themes dropped

The session opened with three captures and nothing built. The multi-user question
was taken first because it decided what the bot is: the sign had been described as
a page on a person's own machine, which meant anyone else wanting one would have
to install and run something. Claude proposed a hosted page instead — one address
per person, opened in a browser tab and screen-shared — and Alex agreed. That
choice removed the local piece entirely and cost SPEC its "self-contained, no
database" principle, which now reads "nothing to install" and admits that who is
AFK and until when has to be stored somewhere.

Cloudflare Workers was chosen over an always-on server. One Worker covers all
three jobs — receiving Discord's requests, holding the state, serving the sign
pages — on a free tier. An always-on server (Railway, Render) lost on having the
same setup effort, an ongoing cost, and three moving parts instead of one.

Before committing to that, the current facts were looked up rather than
remembered, and the lookup changed the plan twice. Discord validates an
Interactions Endpoint URL at the moment it is saved, by sending a test request to
it — so the Worker has to be deployed and answering before the developer-portal
step can happen, which is the reverse of the intuitive order and is why the deploy
step is now its own held item. And every request from Discord arrives signed, so
signature verification is a required part of the build rather than a refinement.
Filed at `resources/research/discord-slash-commands-on-cloudflare-workers.md`.

The build was found not to depend on the Discord application existing, because the
Worker reads the public key from configuration rather than needing the value at
authoring time. That is what let the build and the accounts step both clear rather
than forming a chain.

Timezone was settled without asking: the sign page reports the timezone of the
machine it is open on, and `/afk 3pm` is read against that. It avoids a
server-wide timezone setting and avoids anyone typing an offset.

Themes was dropped on Alex's instruction after the cost was surfaced. The cat
photos are not a search term — `afk-sign_1.html` holds a hand-curated list of
twenty specific Pexels photos, each carrying a note saying whether the text sits
top or bottom because someone looked at that photo and found the cat's face. Each
new theme is therefore twenty photos chosen and individually eyeballed, plus an
undesigned mechanism for choosing one. Recorded here so a later session does not
re-propose it as a small setting.

**Red flag cleared — designed out.** A readable sign address (`/sign/alex`) would
let anyone who guessed it check whether a named person was at their desk, without
that person knowing — presence data on a semi-public server. Alex was given the
choice between readable and random addresses with the trade stated (readable is
easier to type and share deliberately; random means asking the bot if you lose
yours) and took random. Sign addresses are long random strings, and the bot will
tell you yours on request. SPEC carries the sentence.

**[discord-bot] amended at the close, on Alex's direction.** The wind-down
re-scan surfaced a case the random-address decision creates and nothing covered:
an address that leaks cannot currently be replaced. Rather than file it as a
capture behind an already-cleared item, Alex directed it into the build block —
which now carries a command that discards your address and issues a fresh one,
and requires every reply carrying an address to be private to the caller so the
bot never posts one into a channel.
