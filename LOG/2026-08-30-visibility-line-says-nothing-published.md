The risk is narrow and easy to miss. `CLAUDE.md` line 32 said SPEC.md, QUEUE.md
and LOG/ are tracked in a repository with no online home and that nothing is
published anywhere. That sentence is the one every future session reads to decide
how freely it can write. Left standing, a session would put working detail into
the queue and the logs believing it stays local, and all of it would reach a
public repository on the next push. The evidence that this is a real failure mode
rather than a theoretical one arrived the same hour: the scrub run before
publishing found the user's Cloudflare account handle — the local part of their
personal email — written into a deploy record by an earlier session that had no
reason to think anyone would read it.

The one decision in the item was the user's and was not taken by default: whether
the three documents stay public. They stay. Their reason for it, given after the
alternative was put to them: pulling them back would contradict the GitHub issue
filed the same day, which states in public that this repository's queue and logs
are readable if the state of the project is useful to Discord. The alternative
that lost was untracking the three documents so writes from now on stay private;
it lost on two counts, that nothing already pushed can be recalled so it protects
only tomorrow, and that it falsifies a page the user cannot quietly edit.

The `INBOX/` exception is written into the item deliberately rather than left to
be rediscovered. That folder is gitignored, so the correspondence register and the
two reports sent from this project have never left the machine. A session that
does not know this will avoid writing correspondence detail it could safely write,
which is the mirror-image failure of the one the item fixes.
